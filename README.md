# SAMARKAND

Роглайт-экшн, где ты — чудовище. Каждая комната это человеческое поселение: хутор,
деревня, острог, скит. Комната считается пройденной, когда в ней не остаётся живых.
Души — это и опыт: каждый уровень даёт выбор навыка, а на ключевых этапах — необратимая
мутация, которая меняет и характеристики, и то, как монстр выглядит.

Кампания — три биома подряд (деревни → военный лагерь → Собор), по 12 комнат каждый.
Отдельно от неё есть **Орда** — режим выживания против волн, и ежедневный забег на общем сиде.

## Запуск

```bash
npm install
```

```bash
npm run dev
```

Открыть http://localhost:5173

Сборка: `npm run build` (выход в `dist/`, ~180 КБ gzip основной бандл, без внешних
ассетов; SDK аналитики и режим съёмки — отдельные чанки, грузятся только когда нужны).

## Проверки

```bash
npm run check
```

Это типы, линтер и тесты одной командой; по отдельности — `npm run typecheck`,
`npm run lint`, `npm test` (и `npm run test:watch` во время работы). То же самое
гоняется в GitHub Actions на каждый push и pull request, плюс сборка, `npm audit` и
отдельная работа на каждый браузерный движок.

Тесты покрывают то, где ошибка молчит, а не падает: модель урона (броня трогает только
физический, сопротивления — свой элемент, ничто не даёт полного иммунитета), детерминизм
ГПСЧ и независимость его форков, инварианты карты забега (нет тупиков, нет недостижимых
остановок, рёбра не перескакивают полосу), паритет ключей в семи словарях (ru, uk, en, de, fr, it, hr), миграции
сохранений с возвратом душ, потолки и полы характеристик, целостность таблиц контента,
разбор настроек из битого сохранения и логика переназначения клавиш.
Всё это чистые функции — DOM не нужен, и прогон занимает пару секунд.

### Браузеры

```bash
npm run test:e2e
```

Playwright гоняет игру в трёх движках — Chromium, Firefox и WebKit (он же Safari) — на
шести разрешениях от 400×400 до 1920×1080. Часть прогонов идёт по **собранному** бандлу,
как у игрока: грузится, рисует, не молчит в консоль, переживает изменение размера окна,
поднимает звук по первому клику. Часть — по dev-серверу, где есть отладочная ручка:
зачистка поселения от начала до конца, одинаковый забег из одного сида в каждом движке,
монстр действительно нарисован, и замер стоимости кадра в самой тяжёлой арене.

Стоимость кадра, 17 защитников, двенадцатая глубина (медиана из 150 кадров):

| движок | медиана | p95 |
|---|---|---|
| Chromium | 0.4 мс | 0.6 мс |
| Firefox | 2 мс | 4 мс |
| WebKit (Playwright, Windows) | 26 мс | 29 мс |

Бюджет кадра при 60 Гц — 16.7 мс. Цифра WebKit не про Safari: сборка Playwright вне
macOS растеризует канвас программно; она измеряется и печатается, но порог на неё не
ставится.

Чего тесты не проверяют: как игра ощущается, и как она выглядит. Для этого автопрогон
из раздела «Отладка» и живая обкатка.

## Управление

| Клавиша | Действие |
|---|---|
| WASD / стрелки | движение |
| — | **автоатака по ближайшей цели, в том числе на бегу** |
| Пробел / Shift | рывок (неуязвимость на время рывка) |
| Tab | лист формы: характеристики, стихии, навыки, живая статистика |
| Esc | пауза |
| 1 / 2 / 3 | выбор карты или мутации |

Монстр бьёт сам и не требует остановки. Стоять на месте всё равно выгодно: разброс
снарядов сходится к нулю примерно за четверть секунды, а на бегу веер раскрывается
вдвое. Так бег остаётся полноценной опцией, а не наказанием.

## Системы

**Урон.** Шесть стихий: физический, огонь, яд, мороз, молния, скверна (плюс свет —
оружие жрецов). Каждая гасится отдельно: броня трогает только физический,
сопротивления — свою стихию. Поэтому «собрать огненного монстра» и «собрать
пробитие брони» — это разные билды, а не два способа написать «+урон».

**Статусы.** Горение и яд — урон по времени со стаками; охлаждение замедляет и на
десяти стаках замораживает; разряд и проклятие увеличивают получаемый целью урон;
кровотечение усиливается, если цель бежит; ужас обращает в бегство.

**Карта забега.** Путь — не прямая линия, а слоистый граф на 12 глубин: два-три узла в
слое, рёбра только между соседними полосами, поэтому весь маршрут читается без прокрутки.
Перед каждым шагом выбираешь, куда идти:

| Остановка | Что это |
|---|---|
| **Поселение** | обычная зачистка: души и опыт |
| **Гарнизон** | тесная арена, рыцари и жрецы, **две реликвии гарантированы** |
| **Логово падальщика** | без боя: души в обмен на карту, лечение, +здоровье или снятие порчи |
| **Проклятый алтарь** | сильная карта (не ниже редкой) ценой **постоянного проклятия** |
| **Твердыня** | один из боссов текущего биома — открывает путь дальше, а не конец забега |

Маршрут гарантированно содержит минимум две лавки и две элиты, первые две глубины —
обычные бои, а перед боссом слой всегда чистый. Пройденное перечёркнуто, доступное
пульсирует, дальнее видно приглушённым — планировать на три шага вперёд можно.

Этот граф генерируется заново для каждого следующего биома — военного лагеря и Собора —
сразу после босса предыдущего, тем же алгоритмом и с теми же гарантиями. Сложность
(уровень защитников, размер арены, цены в лавке) продолжает расти сквозь все три биома
подряд, не сбрасываясь на границе: 36 комнат одного нарастающего забега, а не три
самостоятельных. Дошедший до биома может в следующий раз начать прямо с него — тогда
это короткий забег со своей, свежей кривой сложности.

**Проклятия.** Десять штук, каждое бьёт по конкретному стилю игры: хрупкие кости режут
здоровье, свинцовые лапы — скорость, дрожь ломает точность, голодная тьма замедляет
набор уровней. Вопрос не «плохо ли это», а «плохо ли это для моего билда». Видны в листе
формы (Tab), снимаются только в лавке.

**Уровни и навыки.** Каждая душа — это и валюта, и опыт. Уровни, набранные в бою,
копятся и тратятся у портала на выходе из комнаты: выбор из трёх карт, а если уровней
несколько — выборы идут один за другим. Посреди драки игра не останавливается. (В Орде
портала нет, поэтому там выбор открывается сразу.) ~45 карт четырёх редкостей: обычные — чистые числа; редкие меняют
способ доставки урона (стихии, снаряды, рикошеты); эпические добавляют поведение,
которое срабатывает само (взрыв трупов, цепная гроза, чумное облако, выводок);
легендарные определяют билд и обычно чего-то стоят.

**Защитники.** В каждом поселении есть и ближний, и дальний бой, начиная с первой
комнаты. Ополченцы и копейщики идут в клинч и держат дистанцию удара, не залезая в
игрока. Лучники и арбалетчики кайтят и требуют укрытия. Жрецы лечат своих. Баллисты
на башнях простреливают всю карту. Крестьяне разбегаются, выдыхаются и в итоге падают
без сил. Тот, кто долго не может ударить, срывается в отчаянную атаку — комната
никогда не превращается в бесконечную беготню.

**Первый босс.** Двенадцатая комната достаёт из сида одного из трёх боссов, и это разные
бои, а не разные полоски здоровья. **Инквизитор** держит дистанцию: кольца святых болтов
с просветом, отложенное освящение земли, подкрепления из ополчения и лучников.
**Воевода** давит вплотную — телеграфированный прыжок с обвалом, ударная волна по
земле, двое рыцарей-телохранителей; сопротивляется физическому урону и холоду.
**Огнедержица** отбирает пространство: стена огня, веер углей, кольцо костров вокруг
себя; почти неуязвима к огню, зато хрупкая. Имя арены меняется вместе с боссом.

**Военный лагерь.** Победа над первым боссом не заканчивает забег, а открывает второй
биом: те же 12 глубин, но выжженная степь вместо деревень, и другой состав защитников —
**всадники**, срывающиеся в атаку почти без промедления, и **осадные машины** при
**твердынях** (более крупная и живучая замена гарнизонной башне с баллистой). Заканчивается
**Хаганом**: тот вызывает подкрепление всадников, бьёт веером дротиков и накрывает арену
слепящей песчаной бурей. Во время любого из четырёх боссов подмешивается отдельный
музыкальный слой — барабан и рог, — которого нет в обычных комнатах.

**Собор.** Третий, финальный биом. Собственный состав, не смешивающийся с прежними:
**флагелланты** (мирные, но не бегут, а лезут в драку), **экзорцисты** (святой урон
издалека, ослабляют) и **паладины**. В каждой комнате стоит **колокольня**: пока она цела,
вокруг неё земля бьёт по монстру и ослабляет его — это первая угроза на земле, которая
работает против игрока, и колокольню надо ломать первой. Финал всего забега — **Анахорет**:
держит вокруг себя святилище, которое наказывает за бой издалека.

Всего боссов пять: три в первом биоме (выпадает один из сида), Хаган и Анахорет.

**Эволюция.** После комнат 4, 8 и 12 — выбор из трёх мутаций. Рога, крылья, лишние
глаза, шипы, элементальные ядра. Монстр рисуется целиком процедурно из описания тела
(`MonsterBody`), поэтому каждая мутация реально меняет силуэт — спрайтов нет.

**Временные облики.** В каждом поселении лежит хотя бы одна реликвия; ещё их роняют
рыцари, жрецы и разрушенные часовни. Подобрал — и на 15–20 секунд становишься другим
существом. Десять форм, и каждая перестраивает тело, а не только цифры:

| Облик | Что видно | Что даёт |
|---|---|---|
| Пламенный облик | огненная аура, тело светится | урон обращается в огонь, земля тлеет |
| Исполин | раздувается в 1.65 раза | +50% здоровья, +35% урона, тяжелее шаг |
| Бесплотность | тело просвечивает, съёживается | +35% уклонения, +40% скорости, хрупче |
| Грозовой венец | рога, жёлтое свечение | цепные молнии, +25% скорости атаки |
| Костяной доспех | дюжина шипов по спине | +70 брони, шипы отражают урон |
| Тысячеокий | десять глаз по телу | +30% крита, наведение снарядов |
| Крылатый ужас | разворачиваются крылья | +30% скорости, +2 рывка |
| Чумное дыхание | зелёная аура, тело пухнет | яд, облака заразы с трупов |
| Рой | распадается на множество лап | +45% скорости атаки, лишний снаряд |
| Ледяное сердце | синеет и покрывается льдом | мороз, ледяная вспышка при рывке |

Формы складываются: можно ходить исполином в огне одновременно. Таймеры видны внизу
экрана. Технически облик — это функция, правящая копию `MonsterBody`; и рендер, и
радиус столкновений берутся из неё, так что исполин действительно занимает больше
места, а не просто рисуется крупнее.

**Стартовое тело.** Забег начинается в одном из четырёх тел, и выбирается оно в логове,
до вылазки. Тело меняет **базовые** статы, а не модификаторы, — поэтому проценты, набранные
за забег, множатся на него, а не топят его собой. **Отродье** ровное во всём. **Ловчий**
быстрый и хрупкий, с двумя рывками и короткой дистанцией. **Исполин** медленный, бронированный,
бьёт редко и тяжело. **Вестник** стреляет парой снарядов, половина урона обращается в
нечестивый, но разлёт широкий и здоровья мало. Отродье и Ловчий доступны сразу, остальные
покупаются за души. Каждое тело — своя процедурная внешность, и в логове она рисуется живьём,
включая запертые: увидеть тварь — и есть причина её захотеть.

**Настройки.** Открываются из меню и из паузы — потому что убавить тряску камеры
хочется обычно уже посреди первого боя, а не до него. Тряска (нет / слабая / полная),
плотность частиц, числа урона, счётчик миллисекунд на кадр, язык, громкость и
переназначение семи клавиш. Язык переехал сюда с главного экрана: три двухбуквенные
плашки в углу легко было не заметить, а «DE» ничего не говорит тому, кто не знает,
что ищет. Список во всю ширину называет каждый язык на нём самом. Всё применяется и сохраняется сразу, кнопки «применить» нет. Ничего из
этого не меняет сложность: настройки правят подачу, а не баланс.

**Мета-прогресс.** Души сохраняются между забегами и тратятся в логове на **разблокировку
контента**, а не на проценты. Из 44 карт, 14 мутаций и 10 обликов свободны только
стартовые 20 карт, 9 форм тела, 3 реликвии и 2 тела — остальные 38 позиций выкупаются и лишь
после этого начинают выпадать в забегах. Логово показывает и запертое: знать, что тебя
ждёт, — половина мотивации. Профиль пишется в `localStorage` с миграциями по версиям.

**Звук.** Полностью процедурный, как и графика: ни одного файла, всё синтезируется
осцилляторами и фильтрованным шумом в момент воспроизведения. Около тридцати звуков —
удары, смерти, обвалы, стихии, интерфейс, — плюс адаптивная подложка из трёх слоёв:
басовый дрон, пэд, открывающийся по мере накала боя, и сердцебиение, слышное только
когда до смерти рукой подать. Мир звучит позиционно: дальние события тише и панорамируются.

Отдельно стоит замах врага — восходящий тон перед ударом. Это единственное, что
позволяет увернуться от того, кого не видно на экране.

Технически: голоса ограничены бюджетом (36 одновременно), одинаковые звуки в одном
кадре схлопываются в один, а на выходе стоит лимитер — двадцать взрывов разом дают пик
0.83 из 1.0 без клиппинга. Громкость настраивается в меню и хранится в профиле.

**Границы.** Арена обнесена видимым барьером — валунами, а в укреплённых поселениях и
у собора кладкой с зубцами. Играбельная зона заканчивается там, где начинается камень,
так что край мира — это предмет, а не невидимая линия. Когда поселение падает, к
порталу ведёт цепочка шевронов рядом с монстром и метка на краю экрана.

**Орда.** Отдельный режим выживания, выбирается в меню. Одна широкая арена, волны
каждые 11 секунд со всех краёв, за пару секунд до волны HUD предупреждает, каждая пятая
волна — с мини-боссом. Задача — продержаться 12 минут. Пять уровней, каждый начинается
с той сложности, на которой закончился предыдущий; следующий открывается только победой,
и поражение уже открытое не отнимает. Уровни и карты — те же, что в кампании, но выбор
карты открывается сразу, а не у портала. Код: [hordegen.ts](src/world/hordegen.ts),
[hordewaves.ts](src/world/hordewaves.ts), числа — [balance.horde.ts](src/balance.horde.ts).

**Статистика.** Экран итогов показывает всё, что записал трекер: урон по типам и
источникам, график DPS, точность, крит, список жертв, взятые навыки и мутации,
время по комнатам, самые опасные враги. Летопись хранит пожизненные суммы и рекорды.

## Устройство кода

```
src/
  audio/       процедурный синтез: движок, каталог звуков, адаптивный эмбиент
  core/        математика, детерминированный RNG, ввод, камера
  combat/      модель урона и статусов (чистые функции)
  entities/    Entity → Combatant → Monster / Human / Projectile / Building / Pickup
  progression/ характеристики, карты навыков, мутации, облики, мета-прогресс
  world/       World (симуляция одной комнаты) и генератор поселений
  render/      Renderer, процедурная отрисовка монстра, ландшафт, частицы
  ui/          иммедиат-режим виджетов поверх canvas, HUD и экраны
  reels/       режим съёмки промо-роликов (?reels), грузится только по запросу
  balance.ts   все числа кампании; balance.horde.ts — числа Орды
  game.ts      игровой цикл и конечный автомат состояний
```

Симуляция идёт фиксированным шагом 60 Гц независимо от частоты кадров. Сущности
никогда не обращаются друг к другу напрямую — только через `World`, поэтому весь учёт
урона и телеметрия собраны в одном месте.

Комнаты генерируются из сида: `generateRoom(index, rng)` полностью описывает
планировку, поэтому забег воспроизводим. Косметическая случайность (частицы, тряска)
идёт из отдельного генератора, чтобы отрисовка не влияла на симуляцию.

## Отладка

В dev-сборке игра доступна как `window.samarkand`:

- `debugSnapshot()` — состояние, позиции, счётчики, список выживших
- `debugFrame(ms)` — прогнать кадр вручную (нужно, когда вкладка скрыта и rAF стоит)
- `debugLoadRoom(n)`, `debugBuff()`, `debugOfferMutations()`, `debugGrantBoon(id)`
- `debugSetBiome(1 | 2 | 3)` — мгновенно перегенерировать карту нужного биома текущего
  забега, минуя обычный путь к нему (нужен уже начатый забег)
- `debugStartHorde(level)` — сразу в Орду нужного уровня, мимо меню
- `debugPlaySound(name)` — проиграть один звук из каталога, для настройки

Автопрогон и снимки экрана: `import('/dev/autoplay.js')`, затем `autoplay()`,
`scene(name)`, `shot(name)`. Снимки пишутся в `dev/shots/` через dev-эндпоинт
`/__shot` (только в режиме разработки, в сборку не попадает).

## Режим съёмки (рилсы)

Студия для промо-роликов в соцсети: открыть игру с `?reels` в адресе —
`http://localhost:5173/?reels` в разработке или `…/index.html?reels` на любой веб-сборке.
Справа появляется панель, игра становится кадром нужного формата, запись идёт прямо
с канваса вместе со звуком игры и скачивается файлом. Панель и разметка в файл не
попадают — они в DOM, а записывается только канвас. На нативных сборках режим выключен.

| Что | Как |
|---|---|
| Формат | 9:16 (1080×1920 — Reels, TikTok, Shorts), 1:1 (1080×1080), 16:9 (1920×1080); для каждого есть и 720p |
| Зоны соцсетей | красным отмечено, где поверх видео будут кнопки и подпись платформы; HUD игры сам уходит из этих зон |
| Чистый кадр | `H` — скрыть весь интерфейс игры, только арена |
| Замедление | `T` — 1× → 0.5× → 0.25×; запись идёт в реальном времени, так что замедление остаётся в ролике |
| Приближение | ползунок 0.6–1.8× поверх обычного зума |
| Сцены | сразу в бой: деревня, деревня глубже, босс деревни, военный лагерь, Собор, финальный босс, Орда |
| Монстр | «Эволюция» — +3 карты и +2 мутации (мутации меняют силуэт, это самое зрелищное); «Усилить ×12»; «Бессмертие» — дубль не оборвётся смертью |
| Запись | `R` или кнопка; автостоп через 15/30/60/90 с |

Файл — MP4 (H.264 + AAC) в Chrome/Edge и Safari, WebM в Firefox; 16 Мбит/с, 60 кадров.
Сохраняется как `samarkand-reel-ГГГГММДД-ЧЧММСС.mp4`. Играешь при этом как обычно, с
клавиатуры; настройки игры (язык, громкость, тряска) действуют и в записи — например,
выключенный звук даст немой ролик.

Как устроено: [reels.ts](src/reels/reels.ts) — панель и раскладка,
[recorder.ts](src/reels/recorder.ts) — `MediaRecorder` поверх `canvas.captureStream()`
и аудиопотока из [engine.ts](src/audio/engine.ts), снятого после лимитера. Кадр
фиксируется через `Renderer.setFixedViewport` (логический размер 432×768 для 9:16 —
как у большого телефона, поэтому работают все мобильные раскладки HUD), а все ручки
игры собраны в `Game.cinema` и методах `startReelsScene`/`reelsEvolve`. Модуль
грузится динамическим `import()`, в бандл обычного игрока не попадает.

## Сборка под Android

Обёрнуто в [Capacitor](https://capacitorjs.com/): [`capacitor.config.ts`](capacitor.config.ts)
указывает на собранный `dist/`, нативный проект лежит в `android/` и уже
закоммичен как обычный исходник — `android/.gitignore`, который сгенерировал
сам Capacitor, вычищает build-артефакты и `local.properties` (в нём абсолютный
путь к SDK конкретной машины, ему в репозитории не место).

Нужны Android Studio и его SDK (переменная `ANDROID_HOME` в системе) — без них
собирать нечем.

```bash
npm run android:sync
```

Пересобирает `dist/` и копирует его в нативный проект. Дальше — либо

```bash
npm run android:open
```

и запуск кнопкой Run в Android Studio, либо сборка из терминала:

```powershell
$env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"
cd android
.\gradlew.bat assembleDebug
```

APK окажется в `android\app\build\outputs\apk\debug\app-debug.apk`.

Две вещи, о которые можно споткнуться:

- **Обязательно PowerShell, не Git Bash.** Gradle падает с `Invalid file path` —
  это MSYS (среда Git Bash) коверкает Windows-пути на пути к нативным
  исполняемым файлам. Тот же самый `gradlew.bat` в PowerShell собирает без вопросов.
- **`JAVA_HOME` — не системная Java.** Из коробки на машине может стоять
  Java 8, а современный Android Gradle Plugin хочет 17+. Проще всего указать
  на JDK, который уже идёт в комплекте с Android Studio (`...\Android
  Studio\jbr`), а не ставить отдельный JDK.

Что уже учтено в коде ради этой платформы:

- **Аппаратная/жестовая кнопка «Назад».** Без обработки Capacitor по умолчанию
  просто закрывает приложение, даже посреди боя. [`main.ts`](src/main.ts)
  подписывается на `backButton` из `@capacitor/app` и превращает нажатие в
  синтетический Escape — тот же путь, которым везде в игре уже работает пауза
  и выход из подменю. На главном экране, где Escape ничего не делает, кнопка
  действительно закрывает приложение.
- **Подсказки под клавиатуру скрываются на тач-устройствах.** «WASD — движение»,
  «TAB — статистика» и подобные строки не имеют смысла там, где физической
  клавиатуры нет; при активном сенсорном управлении они не рисуются
  (`touchActive` в [`hud.ts`](src/ui/hud.ts) и [`screens.ts`](src/ui/screens.ts)).

**Иконка и splash больше не заглушки Capacitor.** Источники — в
[`assets/`](assets/) (`icon-foreground.svg`, `icon-background.svg`, `icon-only.svg`,
`splash.svg`), тот же силуэт, что и инлайновый favicon в [`index.html`](index.html).
Растеризованы через `@capacitor/assets` в Custom Mode во все плотности
`android/app/src/main/res/mipmap-*` и `drawable-{port,land}-*`. Эти PNG — обычные
бинарные ассеты и закоммичены как есть; сама генерация — разовая операция
(`npx @capacitor/assets generate --android` при исходниках в `assets/`), инструмент
после неё можно снести — он тянет уязвимые транзитивные зависимости и иначе
портит `npm audit` в CI. Если пересобирать иконку, `npm install -D
@capacitor/assets`, прогнать генератор и `npm uninstall @capacitor/assets`.

**Release-сборка подписывается настоящим ключом**, не debug-сертификатом.
[`android/app/build.gradle`](android/app/build.gradle) читает путь и пароли из
`android/keystore.properties` — файла нет в репозитории (`android/.gitignore`
исключает его вместе с `*.jks`/`*.keystore`), у каждой машины и CI свой. Без
файла `assembleRelease`/`bundleRelease` всё равно соберутся, только не подписанными
— гейт только на публикацию, не на билд. Сам ключ создаётся один раз:

```powershell
$env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"
keytool -genkeypair -v -keystore android/samarkand-release.jks -alias samarkand-release `
  -keyalg RSA -keysize 2048 -validity 10000 -storepass "<пароль>" `
  -dname "CN=Samarkand, O=Samarkand, C=CH"
```

и рядом кладётся `android/keystore.properties`:

```properties
storeFile=samarkand-release.jks
storePassword=<пароль>
keyAlias=samarkand-release
keyPassword=<тот же пароль — PKCS12 не различает store- и key-пароль>
```

Дальше `assembleRelease`/`bundleRelease` (та же PowerShell-обвязка, что и выше)
подписывают билд автоматически. **Файл ключа и пароли нужно унести в отдельное
хранилище (менеджер паролей, секреты CI) сразу после создания** — потеря ключа
не убивает приложение навсегда (Play App Signing позволяет сбросить upload-ключ
через поддержку Google), но без бэкапа это лишний повод писать в поддержку.

**`.aab` для Play одной командой:**

```bash
npm run android:bundle
```

Пересобирает веб-бандл, синкает его в нативный проект и гонит `bundleRelease` —
результат в `android\app\build\outputs\bundle\release\app-release.aab`. Работает
что из PowerShell, что из Git Bash (сам скрипт всегда выполняется через `cmd.exe`,
это поведение самого npm на Windows, а не терминала, из которого его запустили).
Внутри — та же связка `JAVA_HOME` + `gradlew.bat`, что и выше, с одной
дополнительной деталью: вызов именно `.\gradlew.bat`, а не голый `gradlew.bat`, —
на машинах, где выставлена системная переменная
`NoDefaultCurrentDirectoryInExePath`, `cmd.exe` не ищет исполняемые файлы в
текущей директории без явного `.\`, и без этой точки команда падает с
`'gradlew.bat' is not recognized`, хотя файл лежит там же. Собрать `.apk`
вместо `.aab` — `android/gradlew.bat assembleRelease` тем же способом.

`appId` — `onyx.system.samarkand` (Android `applicationId`/`namespace` в
[`build.gradle`](android/app/build.gradle), пакет `MainActivity` и
[`capacitor.config.ts`](capacitor.config.ts) заведены под него). После первого
релиза в Play его сменить будет нельзя. Перед публикацией остаётся завести
аккаунт Google Play Console.

## Реклама

Rewarded-видео используется в двух местах: возрождение после смерти (раз за забег) и
бесплатная пересдача карт в лавке падальщика (там выбор карт продаётся за души, так что
реклама — осмысленная альтернатива плате). На обычном выборе карт за уровень её нет.

Реклама спрятана за интерфейсом `AdService`
([ads.ts](src/core/ads.ts)) — `Game` и UI никогда не обращаются к рекламному SDK
напрямую, только к `isRewardedAdAvailable()`/`showRewardedAd()`. Какая реализация
подставляется, решает `resolveAdService()` в [main.ts](src/main.ts:41): на нативном
Android — `AdMobAdService`, на вебе — портал из `VITE_AD_PLATFORM` (`crazygames` /
`poki`) или, если билд без портала, `NoAdsService`/`SimulatedAdService` (в dev).

Android использует `@capacitor-community/admob`, подключён так же лениво, как
портальные SDK — динамическим `import()` внутри `AdMobAdService`, чтобы веб- и
портальные сборки не платили размером бандла за код, который им не нужен.
Перед первой реальной загрузкой в Google Mobile Ads SDK сервис проходит
UMP-флоу (`requestConsentInfo` → `showConsentForm`), это требование Play для
игроков из EEA/UK, и вызывается независимо от региона — дешевле, чем определять
регион самому.

Оба ID реальные, из консоли AdMob (приложение Samarkand):

- **App ID** — `ca-app-pub-1918664364236470~1009155836`, лежит в
  `admob_app_id` в
  [values/strings.xml](android/app/src/main/res/values/strings.xml) и
  подставляется в `<meta-data>` манифеста. Это нативная настройка на этапе
  сборки Android, а не JS-рантайм — `VITE_`-переменные её не касаются, менять
  нужно саму строку. Приложение в AdMob создано без привязки к листингу в Play
  (его там ещё нет) — привязать можно будет позже из настроек приложения в
  AdMob, без смены App ID.
- **Ad unit** (rewarded) — `ca-app-pub-1918664364236470/8943486173`, лежит в
  [`.env.production`](.env.production) как `VITE_ADMOB_REWARDED_UNIT_ID`.
  Vite подхватывает `.env.production` сам при любой обычной сборке (`vite
  build` по умолчанию в режиме production) — руками ничего экспортировать не
  нужно, `npm run android:bundle` работает как есть. Дефолт на тестовый ID
  Google остаётся в [ads.ts](src/core/ads.ts) только на случай отсутствия
  файла.

Раз ad unit настоящий, `isTesting` в `AdMobAdService` теперь `false` — живая
реклама, не тестовый ролик Google. **Не смотри и не кликай собственную рекламу
руками** — это невалидный трафик по правилам AdMob, при частом повторении
грозит ограничениями на аккаунте.

Безопасно тестировать можно так:

- **Эмулятор Android** ничего настраивать не нужно — Google Mobile Ads SDK сам
  узнаёт эмулятор и всегда отдаёт ему тестовые ролики, независимо от
  `isTesting` и реального ad unit. Подтверждено логом `Ads: This request is
  sent from a test device.`
- **Реальный телефон** — нужно явно зарегистрировать устройство. Один раз
  запусти сборку с реальным ad unit на телефоне, открой `adb logcat`,
  отфильтруй по тегу `Ads`; при первом запросе рекламы SDK печатает готовую
  строку вида `Use RequestConfiguration.Builder().setTestDeviceIds(Arrays.asList("XXXXXXXX"))`
  — это и есть id устройства. Положи его в **гитигнорённый** `.env.local`
  (не в `.env.production` — это личное устройство, а не свойство сборки):

  ```
  VITE_ADMOB_TEST_DEVICE_IDS=XXXXXXXX
  ```

  Можно перечислить несколько через запятую. `AdMobAdService`
  ([ads.ts](src/core/ads.ts)) сам подставит `initializeForTesting: true` и
  `testingDevices`, если переменная не пуста.

**Свежесозданный аккаунт AdMob какое-то время не может отдавать рекламу вообще**
— пока Google не проверит и не одобрит его, любой запрос падает с `Account not
approved yet` (это ограничение аккаунта, не привязано к конкретному ad unit
или коду; проверено на этом проекте — ошибка ушла бы сама после одобрения).
Это нормально для нового аккаунта и требует только подождать, ничего чинить не
нужно.

Отдельно: если UMP-форма согласия ещё не настроена в AdMob (Privacy &
messaging), `requestConsentInfo()` возвращает ошибку `Publisher
misconfiguration`. `AdMobAdService.init()` эту ошибку глотает и продолжает
инициализацию без согласия — реклама не рушится из-за недонастроенного
consent-flow, но для игроков из EEA/UK форму всё равно стоит донастроить в
консоли до реального релиза.

`INTERNET`/`ACCESS_NETWORK_STATE` в манифесте и разрешения, которые сам
подмешивает Google Mobile Ads SDK (`AD_ID`, `ACCESS_ADSERVICES_*`), нужны
рекламе — без них показывать нечего.

## Аналитика

[GameAnalytics](https://gameanalytics.com), за интерфейсом `AnalyticsService`
([analytics.ts](src/core/analytics.ts)) — так же, как реклама за `AdService`: `Game`
сообщает, *что произошло* в игре, и не знает, куда это уходит. Бэкенд выбирает
`resolveAnalytics()` в [main.ts](src/main.ts):

- для текущей платформы заданы ключи (см. ниже) → GameAnalytics (SDK ~23 КБ gzip
  подгружается динамическим `import()`, без ключей не скачивается вообще);
- dev без ключей → `RecordingAnalytics`: события пишутся в память,
  `window.samarkand.debugAnalytics()` показывает ровно то, что ушло бы в GA;
- релиз без ключей → ничего.

**Подключить:** в GameAnalytics каждая платформа — отдельная игра со своими ключами,
поэтому заводится три игры в одной студии: Samarkand Web, Samarkand Android, Samarkand
iOS. Ключи (Game Key и Secret Key из настроек каждой игры) — в `.env.production.local`
(он в `.gitignore`: репозиторий публичный, а ключи дают любому слать события в твою
статистику; `vite build` читает его поверх `.env.production`), затем пересобрать:

```
VITE_GA_WEB_GAME_KEY=...
VITE_GA_WEB_SECRET_KEY=...
VITE_GA_ANDROID_GAME_KEY=...
VITE_GA_ANDROID_SECRET_KEY=...
VITE_GA_IOS_GAME_KEY=...
VITE_GA_IOS_SECRET_KEY=...
```

Бандл один на все платформы (`android:sync` и `ios:sync` берут тот же `vite build`),
так что нужная пара выбирается во время работы по `Capacitor.getPlatform()`
(`gameAnalyticsKeys` в [analytics.ts](src/core/analytics.ts)). Платформа без своей пары
ничего не шлёт и вопрос о согласии не показывает — можно подключать по одной.

Ключи — не пароль: веб-SDK GameAnalytics так и задуман, они позволяют только слать
события. Для портальных сборок (CrazyGames, Poki) сначала проверь правила портала
насчёт сторонней аналитики — сборку без ключей делать можно в любой момент.

**Что отправляется** (всё — в `game.ts`, методы `reportRunStart`/`reportRunEnd` и рядом
с каждым действием):

| Тип GA | Событие | Зачем |
|---|---|---|
| Progression | `campaign` / `daily` / `horde:levelN` — старт, победа, поражение; score — пройдено комнат или секунд в Орде | воронка забега |
| Progression | `campaign:biome2:room07` — старт, зачистка (score = % здоровья), провал | **где умирают**, какая комната — стена |
| Design | `run:start:<режим>:<тело>:<биом>`, `run:end:<режим>:<victory/death/quit>` (= секунды) | как и чем заканчиваются забеги, кто бросает |
| Design | `run:killer:<режим>:<id врага>` | кто убивает |
| Design | `card:pick:<level/market/cursed>:<id>`, `mutation:pick:<id>`, `curse:take:<id>`, `market:buy:<вид>`, `card:reroll:souls` | что выбирают — баланс карт |
| Design | `horde:wave:levelN` (= волна), `trial:<id>`, `perf:frame_ms:<touch/desktop>` | Орда, испытания, производительность у живых игроков |
| Resource | души: `source` за забег, `sink` за покупки в логове | экономика мета-прогресса |
| Ad | rewarded: `show` / `rewarded` / `failed`, placement `revive` / `reroll` | досматривают ли рекламу |
| Error | первая строка ошибки кадра | падения у игроков |

**Согласие — opt-in.** При первом запуске поверх главного меню игрок видит вопрос
([consent.ts](src/ui/consent.ts)) с двумя равноценными кнопками — «Разрешить» и «Не
отправлять»; до ответа не отправляется ничего. Спрашиваем всех, а не только ЕС: чтобы
угадать регион, пришлось бы отправить IP до согласия. Потом выбор меняется в
настройках (раздел «Приватность»). Пока сбор выключен, SDK даже не инициализируется —
это важно, потому что `initialize` в GameAnalytics сам шлёт запрос с id установки и
устройством, даже при выключенной отправке событий. Сохранение, где «да» записано без
отметки о заданном вопросе, считается за «нет» и спрашивает заново. В режиме
съёмки (`?reels`) ничего не отправляется. Что и как описано для игроков — в
[PRIVACY.md](PRIVACY.md); **хостед-копию политики на onyx-systems.ch нужно обновить
вместе с файлом.**

## Приватность

Игра не имеет сервера и аккаунтов: весь прогресс лежит в `localStorage` браузера
(на Android — в локальном хранилище приложения) и никуда не отправляется,
аналитики нет. Единственное исключение — необязательная rewarded-реклама на
Android (см. «Реклама» выше): выбор посмотреть ролик отдаёт немного данных
Google. Текст политики — [PRIVACY.md](PRIVACY.md), это исходник; рабочая ссылка
для Play Console / App Store Connect —
<https://onyx-systems.ch/privacy/samarkand>, страница должна совпадать с файлом.
Меняя, чем игра распоряжается данными, — обновлять оба сразу.
